# 日常视频来源选择

日常观看、分享和投币优先使用配置中的主播。观看和分享随后尝试关注列表，最后使用排行榜。投币依次尝试配置主播、特别关注、普通关注和排行榜，并继续检查每个视频的已投币数量与原创/转载限制。

## 查询失败时的行为

如果一个优先来源返回业务错误、网络请求异常或无法解析的响应，记录原因并尝试下一个已有来源。查询成功时保留原有优先顺序。备用来源用于选择其他公开视频，不改变被拒绝接口的权限。

取消操作会停止后续查询。观看和分享全部关闭，或已开启的操作均已完成时，不查询视频来源。空主播列表、无效主播 ID 和空排行榜分别按无候选或缺少有效数据处理。

主播视频查询的错误响应可能没有 `data`，也可能返回 `data: null` 或 `data: {}`。分页信息允许缺失，使调用方先读取错误码和错误说明。成功响应缺少分页信息时报告明确的数据错误。

投币资格检查使用当前账号的登录 Cookie 查询视频详情，并保持网页来源请求头。视频详情返回业务错误或缺少数据时，保留明确的失败结果，不把未知的原创或转载类型当作可投币依据。

## 回归验证

每日分享改用 `/x/share/finish` 提交客户端分享完成记录，使用当前账号的 Cookie 和所选视频的 `oid`、`sid`。候选视频缺少 `cid` 时先查询登录账号可访问的视频详情，视频不匹配或信息不完整时停止上报。接口使用参考 [BiliOutils](https://github.com/catlair/BiliOutils/blob/61167886bdac0ced38a07347c96103369e8af3e1/src/net/video.request.ts) 和 [BiliRoamingX](https://github.com/BiliRoamingX/BiliRoamingX/blob/ae58109f3acdd53ec2d2b3fb439c2a2ef1886221/integrations/app/src/main/java/app/revanced/bilibili/patches/main/CouponAutoReceiver.kt)。网页分享次数接口仍保留，日常任务不再将其受理结果作为奖励依据。

提交成功和重复分享响应都需要进一步查询今日奖励状态。只有 B 站返回 `share=true` 才显示完成与经验奖励。分享检查项重新参与已启用的自动补做，遵守每日次数上限，并在执行前重新查询完成情况。

提交后最多查询三次今日进度，查询期间不重复分享。尚未确认时显示等待确认，进度暂时不可用时显示明确原因。取消操作会结束查询。

`DailyVideoSelectionTests` 覆盖优先来源成功、业务拒绝、网络故障、空候选、无效 ID、排行榜拒绝、取消操作、投币资格检查和关闭操作。

`VideoSearchResponseTests` 使用 Refit 和本地 HTTP 响应替身，验证三种缺少分页的错误信封均保留业务错误码，以及视频详情查询传递明确的账号 Cookie 和网页来源请求头。验证过程不连接 B 站，不执行真实活动或通知。

`ShareCompletionTests` 覆盖即时确认、延迟确认、未确认、重复分享、奖励查询失败和取消操作。分享请求的回归检查覆盖登录信息、网页请求头和任务来源参数。

客户端完成上报的回归检查覆盖接口路径、视频参数、账号参数、缺失视频信息及取消查询。真实请求受理与每日经验到账分别记录，已完成当天分享时的测试不作为自动获取经验的证明。
